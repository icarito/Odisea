# FD-053.1: Test — Dome_Crio → Airlock → Exterior Transition

**Status:** Spec
**Priority:** High
**Effort:** Small
**Created:** 2026-06-06
**Parent:** FD-053 (AirlockManager)

## Objective

Create a GdUnit test that spawns the player inside `Dome_Crio.tscn`, teleports them to an airlock position, walks them toward the exit door, and measures/validates the transition to OdiseaExterior.

This test validates the AirlockManager system (FD-053). Claude is working on FD-053 in parallel. The test should run against the current AirlockZoneV2 + SceneManager flow as baseline, then against AirlockManager once implemented.

## Test File

- `core_v2/tests/test_dome_crio_airlock_transition.gd` (new)
- Test framework: GdUnit (extends GdUnitTestSuite)

## Test Phases

### Phase 1: Setup

1. Load `Dome_Crio.tscn` in a test scene tree
2. Create a FakePlayer (KinematicBody, add_to_group("player"), with velocity tracking)
3. Position the player at a known position near an AirlockZoneV2 trigger zone inside Dome_Crio
4. Verify the player overlaps the AirlockZoneV2 (zone detects the player via _on_zone_entered)

### Phase 2: Zone Progression

5. Simulate the player moving toward the airlock door (advance position toward zone center)
6. Track `_progress` value (0→1) each frame
7. Verify progress advances linearly as player approaches the exit point
8. Measure: frames from enter to TRIGGER_PROGRESS (should be consistent)

### Phase 3: Transition Trigger

9. At `_progress >= TRIGGER_PROGRESS` (0.6), verify that:
   - `_has_triggered` is set to true
   - AirlockManager.request_transition() (or SceneManager.load_scene()) is called with the correct target
   - target_scene == "res://core_v2/levels/OdiseaExterior.tscn"
   - target_spawn_id == expected spawn point

### Phase 4: Player Snapshot

10. Validate `_build_state_data()` captures:
    - airlock_relative_position (within 0.1m of expected)
    - airlock_relative_velocity (matches player velocity)
    - controller_mode, gravity_mode
    - dome_id from player metadata

### Phase 5: Door Animation Timing

11. Track: door_close_time (expected 0.3s for inter-scene)
12. Track: TransitionLayer fade-out
13. Track: total transition time from trigger to target ready

### Phase 6: Destination Resolution (stub)

14. Verify DomeRegistry.get_spawn_transform(spawn_id) resolves to a valid (spiral, plate) pair
15. Stub: verify the transform is non-zero and matches expected coordinates

## Key Measurements

| Metric | Expected | Method |
|--------|----------|--------|
| Zone detection time | < 3 frames from entering zone | Track _process cycles |
| Progress monotonic | 0→1, never decreases | Assert _progress each frame |
| Trigger threshold | _has_triggered at 0.6 | Assert at _progress >= 0.6 |
| Snapshot position error | < 0.1m | Compare player.pos vs state_data |
| Snapshot velocity error | < 0.01 m/s | Compare player.vel vs state_data |
| Door close duration | 0.3s | Measure from trigger to door closed signal |
| Target scene | OdiseaExterior.tscn | Assert request_transition param |
| Resolved spawn transform | Non-zero | Assert DomeRegistry lookup |
