# FD-050.1 — Rails siempre presentes + openings consistentes

**Parent:** FD-050 — Pasarelas y Andamios Procedurales (WFC 2D)
**Status:** Spec — listo para implementar
**Scope:** Acto I — Gap casco-espirales
**Branch:** `fd-050-scaffold-wfc-17347442582962886612`

---

## Problema

Actualmente `_apply_rails_from_connections` usa `rail = NOT connection`. Esto deja lados de conexión completamente abiertos (sin rail). Además `_apply_opening_widths_from_connections` solo setea el opening del lado local, sin verificar que coincida con el vecino.

## Regla deseada

| Condición | Rail | Opening |
|-----------|------|--------|
| Lado con conexión a vecino | `true` | `lane_width()` |
| Lado sin conexión | `true` | `0` (default) |

Resultado: **rails en TODOS los bordes**, con huecos del ancho de pasarela donde dos módulos se tocan. Los openings entre vecinos conectados deben coincidir en ancho y posición.

### 2. `core_v2/tests/scaffold/TestScaffoldRailConsistency.gd`

**Cambio de invariante.** La verificación actual:
```
connection=true  → rail=false (open)
connection=false → rail=true  (closed)
```

Debe cambiar a:
```
rail=true SIEMPRE
connection=true  → opening_width = lane_width
connection=false → opening_width = 0 (o no seteado, default 0)
```

Para validar openings sin instanciar escenas, se puede verificar desde los datos de variante:
- Si `v.connections[dir]` es true → el generador seteará `opening_width = _lane_width()` → correcto.
- Si `v.connections[dir]` es false → el generador no toca `opening_width` → default 0 → correcto.

Agregar un segundo nivel de validación instanciando la escena (como hace `_instance_grid`) y verificando los valores reales de `rail_*` y `rail_*_opening_width`.

### 3. `core_v2/tests/scaffold/TestScaffoldOpenings.gd`

Agregar check de **matching entre vecinos**: para cada par de celdas conectadas `(A, B)` en dirección `dir`:
- `A.rail_<side>_opening_width == B.rail_<opposite_side>_opening_width`
- Ambos deben ser `== _lane_width()`

Este check requiere instanciar los módulos o inferir los valores desde la variante + reglas del generator.
